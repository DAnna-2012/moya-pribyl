# Запуск «Моя прибыль» в Timeweb

Состояние: код подготовлен. Публикация и запись в реальную PostgreSQL ещё не проверены. Сбор настоящих контактов по умолчанию выключен.

Фреймворк: Flask. Сборка: `pip install --upgrade -r requirements.txt`.
Запуск: `gunicorn main:app --bind 0.0.0.0:8000 --timeout 60 --workers 2`.
Проверка состояния: `/health`. Корневая директория: пустое поле.

Переменные окружения (только в закрытых настройках Timeweb):
- `DATABASE_URL`: строка подключения к PostgreSQL в России. Использовать SSL, например `sslmode=verify-full` и сертификат провайдера. Не публиковать строку в GitHub и чате.
- `LEADS_ENABLED`: `false` до завершения проверки, затем `true`.
- `ADMIN_TOKEN`: случайный секрет не короче 32 символов. Только для закрытой выгрузки, в код страницы не включать.

При первой заявке создаются схема `moya_pribyl` и таблица `leads`. Пользователю базы нужны соответствующие права. Лучше отдельная база и пользователь; не подставлять доступ к чужому приложению без проверки прав и резервных копий.

Выгрузка: GET `/admin/leads.csv` с заголовком `Authorization: Bearer <ADMIN_TOKEN>`. Секрет не передавать в URL. Для просмотра использовать доверенный клиент API.

Перед открытием настоящих заявок:
1. Проверить местонахождение базы и резервных копий в РФ, доступ и шифрование.
2. Проверить сведения оператора в privacy.html/consent.html и уведомление Роскомнадзора; при необходимости дополнить фактические сведения о размещении и обработчиках.
3. Настроить ежедневное удаление просроченных заявок в PostgreSQL: `DELETE FROM moya_pribyl.leads WHERE created_at < now() - interval '90 days'`. Резервные копии также должны иметь ограниченный срок хранения. В коде дополнительно удаляются просроченные записи при новом сохранении.
4. Настроить согласие на необязательную аналитику согласно применимым требованиям. Вебвизор выключен в коде страницы.
5. При закрытом внешнем доступе включить форму для теста, отправить вымышленный контакт и проверить запись в БД, повтор той же заявки не должен добавлять дубликат. Проверить недоступную базу: форма должна сообщать об ошибке, цель заявки не должна срабатывать.
6. Проверить обе цели Метрики. В этой версии `lead_submit` вызывается только после положительного ответа сервера о записи.
7. Перед распространением новой ссылки обновить адрес сайта в Метрике: счётчик принимает данные только с разрешённого адреса GitHub Pages.

Статический GitHub Pages не выполняет Python. На нём обновлённая форма будет закрыта до переноса на Timeweb. Расчёт калькулятора остаётся доступным. Отправка в Google удалена.
